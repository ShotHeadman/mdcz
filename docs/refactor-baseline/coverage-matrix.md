# Coverage matrix

Paths are relative to the repository root. The matrix maps behavioral contracts to existing coverage; it does not prescribe a test for each implementation helper. Phase 0 has not started.

| Contract | Evidence / existing suite | Preservation rule |
| --- | --- | --- |
| Write leaves source contents and location intact; move indexes the relocated video and removes its source | Server `app.observable-baseline.integration.test.ts`; desktop `file_scraper_multipart.test.ts` representative matrix | Preserve across both hosts, one/two parts and both device conditions. |
| Multipart is one movie, one aggregation, all member contents retained | Both representative matrices; server `app.scrape.integration.test.ts` selected-parts live payload/part identity; desktop multipart suite | Preserve successful grouping and part identity. |
| Same-device rename; cross-device required copy and capacity failure protection | Both matrices; `packages/runtime/src/publication/publishMedia.test.ts` capacity/recovery cases | Matrices inject EXDEV, assert one fallback per video; existing failure tests retain originals and prevent commit. |
| Download/NFO output and library asset indexing | Server baseline uses real PNG downloads/NFO; server scrape integration full pipeline | Preserve output facts. Image processing copies are measured separately from publication copies. |
| Desktop/server runtime adapter parity | Both matrices, server full scrape integration, desktop scraper snapshot and create-run suites | Video/library facts agree. Desktop baseline stubs producers; IPC and live crawler parity are outside the measured boundary. |
| Registered ownership prevents unauthorized target mutation | `packages/runtime/src/publication/participants.test.ts`, `preparePublicationPlan.test.ts`, `registered.test.ts`, `publishMedia.test.ts`; desktop multipart ownership cases | Preserve ownership checks, identity, and no commit on conflicts. |
| Source/target changes after preparation are detected; locks reject concurrent path ownership | `publishMedia.test.ts`, `packages/runtime/src/library/mediaPathOwnership.test.ts`, desktop multipart preparation timing cases | Preserve race and busy-path protection until replacement architecture proves equivalent protection. |
| Failed publish/commit restores originals; journals permit recovery and repair reporting | `publishMedia.test.ts`, `recoverPublications.test.ts`, `commitScrapeTerminalResult.test.ts`; `packages/persistence/src/publicationJournalRepository.test.ts` | Preserve source safety and database consistency. Write journal removal is intentional later, not an existing invariant. |
| Subtitle suffixes, bytes, ownership and feature scope | Desktop `file_scraper_subtitle_sidecars.test.ts`, `subtitle_sidecars.test.ts`; multipart retained-feature/version/maintenance test; server subtitle integration | Preserve language/forced suffixes and movie-scoped shared features. Additional desktop feature trace records initial three-part commit. |
| STRM behavior and metadata-only source retention | Desktop `file_scraper_strm.test.ts`; server scrape integration metadata-only/STRM cases | Preserve generated content and source retention; matrix write is preserve output, not a separate metadata-root/STRM workload. |
| Existing artifacts and disabled downloads are retained | Desktop `download_manager_keep.integration.test.ts`, `scene_image_downloader.test.ts`; runtime output/registered artifact tests | Preserve retention choices and no unintended replacement. |
| Run/item/attempt history, retry, snapshot and terminal-library linkage | `packages/persistence/src/scrapeRunRepository.test.ts`; server scrape integration; desktop `scraper_service_snapshot.test.ts`; `tests/unit/services/scraper/scraper_service_create_run.test.ts` | Preserve user-facing status and linkage. Attempt/retry/schema implementation is intentionally revised by later phases. Released migrations stay immutable. |
| Maintenance preview/approval/apply and actor outputs | `packages/runtime/src/tasks/session/MaintenanceSession.test.ts`, maintenance coordinator tests; desktop maintenance actor/preview tests | Preserve approval lifecycle and output safety separately from scrape lifecycle. |
| Canonical roots, path confinement and discovery filtering | `packages/runtime/src/library/desktopInputRoot.test.ts`, publication path/participants cases; desktop `local_scan_service.test.ts`; server directory-scope integration | Existing coverage anchors Phase 0. Ref-list trace does not measure recursive discovery. |
| Current partial member success and target replacement | Desktop multipart missing-member cases; server preflight isolation and runtime uncensored cases; publisher existing-target cases | Record current behavior, but plan explicitly changes group atomicity and move overwrite. Review and replace those expectations when the relevant phase ships. |
| Translation request grouping | Existing translation/output tests; representative fixture has translation disabled | Not measured for enabled HTTP translation. Do not claim the static N-request assumption has been validated. |

Directory prefixes: server suites are under `apps/server/src`; desktop suites under `tests/desktop-integration/services/scraper`; runtime publication suites under `packages/runtime/src/publication`.

Only redundant server aggregation-count/file-count assertions were deleted. Distinct failure, concurrency, retention, identity, lifecycle and recovery cases remain. The matrix replaces the need to duplicate those cases around each planned replacement helper.
